# Hackstack app

The conventions are in [AGENTS.md](../../../AGENTS.md) at the repo root. Read it first; this is the checklist for applying it.

## Adding an app

1. **Gather facts from upstream** before writing anything: the published image and its tags, the port it listens on, the uid it runs as, the tools in the image (for the healthcheck), every environment variable it reads, the config files it uses, and whether it needs a database, Redis, MQTT, mail or the Docker socket. If upstream has its own production compose file and `.env.example`, start from those.
2. **Pick the namespace**: `experiments/<app>` unless told otherwise.
3. **Write `docker-compose.yml`** to the AGENTS.md pattern: `${IMAGE_VERSION:-...}`, `container_name`/`hostname` = app name, `restart: unless-stopped`, `env_file: .env`, relative bind mounts under `../../lib|log|run/<app>` and `./config`, commented-out `ports:`, only the networks it needs, a healthcheck.
   - Shared PostgreSQL/MariaDB, never a bundled one. Per-app Redis on a private network.
   - No host networking unless nothing else works; macvlan overlay if it must appear on the LAN.
4. **Add overlays** for anything a deployment would choose differently (NFS, macvlan, GPU backend, published ports vs proxy networks), enabled through `COMPOSE_FILE` in `.env`. The user must never need to edit a compose file.
5. **Write `.env.example`** with every variable, secrets as `<FILL IN>` placeholders, optional settings commented out, hosts as container names, no `BACKUP_DATABASE_URLS`.
6. **Add `config/*.example`** for config files and git-ignore the real ones.
7. **Add `.gitignore`** (`.env` and real config files) and, if there are live database files under `../../lib/<app>`, `.rsync.exclude`.
8. **Write `README.md`** from `docs/app-readme-template.md`: what it is, required settings, database/data-directory/ownership setup, proxy target, overlays, anything unusual, usage.
9. **Check** with `docker compose config -q` (copy `.env.example` to `.env`, then delete it) for every overlay combination.
10. **Look for references**: does Prometheus scrape it (`experiments/prometheus/config/prometheus.yml.example`)? Does another app connect to it?

## Moving or deprecating an app

`git mv` the directory, then `git grep` for the app name and old path: `bin/install-*.sh`, `docs/`, other apps' READMEs and compose networks, and the Prometheus example config. Point out apps that depend on it (for example its network).

## Never

- Commit secrets, real `.env` files or real config files.
- Edit the top-level `.gitignore` or `.rsync.exclude` (generated by GitHub Actions).
- Tell the user to edit a compose file.
- Run, install or start the stack unless asked.
